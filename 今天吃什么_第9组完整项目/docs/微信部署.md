# 微信小程序和云开发部署

当前交付默认使用本地演示。真实微信环境没有配置或部署，以下步骤需在你们自己的小程序和云环境中完成。本地模拟测试通过不等于微信接口已经连通。

## 一 导入并运行本地模式

1. 从微信官方渠道安装微信开发者工具，登录你们的开发者微信。
2. 选择“导入项目”，目录选本包根目录，即包含 `project.config.json` 的目录。
3. 本地演示可选择工具支持的测试号或无AppID模式；若该工具版本不允许相关能力，填入你们已有的小程序AppID。配置中的 `touristappid` 只用于演示，不是正式账号。
4. 保持 `miniprogram/config.js` 中 `mode: 'demo'`。选择当前稳定基础库并编译。无需构建npm。
5. 页面底部应有今天吃啥、逛食堂、排队实况、好味榜、我的五个标签。到“我的”使用体验身份登录。

本机没有检测到微信开发者工具，因此这一步的实际编译结果、微信原生渲染和真机操作仍待验证。项目中提供了9个页面的配置、脚本、WXML与WXSS，并已做页面控制器模拟测试。

## 二 准备真实云环境

1. 使用拥有云开发权限的真实小程序AppID，替换 `project.config.json` 的 `appid`。不要把 AppSecret 写进代码。
2. 在开发者工具开启微信云开发，创建或选择已有环境。云资源费用按你们账号规则产生；本交付未替你们创建付费资源。
3. 在 `miniprogram/config.js` 填 `envId`，把 `mode` 改为 `cloud`。
4. 确认工程的 `cloudfunctionRoot` 为 `cloudfunctions/`。对 `campusApi` 和 `notifyMeals` 分别右键，选择“上传并部署：云端安装依赖”。函数使用 `wx-server-sdk` 3.0.1；不用将 node_modules 打入小程序。
5. 两个函数建议使用平台支持的 Node.js 18 或更新运行时、60秒超时。平台控制台参数优先于本地配置。
6. **campusApi 只允许小程序云调用，不配置HTTP访问或Web触发。** 代码校验调用来源并从 `getWXContext()` 获取身份。
7. 复制 `cloudfunctions/database.rules.json` 的规则到全部业务集合，设为客户端不可直接读写；所有读写经云函数。数据库权限配置不会因打包这个JSON而自动生效，必须在控制台逐集合设置。
8. **1.2必须更新云存储规则**：在控制台应用 `cloudfunctions/storage.rules.json`。客户端不能直接读云文件，只允许已登录微信用户写入本人拥有的 `reviews/` 原图；`verified/` 不允许客户端创建、覆盖或删除。云函数完成检查后把同一份已检查字节复制至该冻结目录，仅为有权查看的评价生成签名读图地址。云端只接受JPG/PNG，每张1MB以内、最多3张。
9. 验证规则生效后，给campusApi环境变量设置 `SECURE_STORAGE_RULES_ACK=v1.2`；没有此值不会签发上传票据或接收图片。仅上传JSON不会自动应用规则，此标记也不代替真实权限验证。

## 三 获取管理员身份并初始化

在开发者工具的“小程序调试器 Console”中调用：

```javascript
wx.cloud.callFunction({name:'campusApi',data:{action:'whoami'}})
  .then(r => console.log(r.result));
```

返回当前开发者的 `openid`。将实际值填入 **campusApi 云函数的环境变量 `ADMIN_OPENIDS`**，多个管理员用英文逗号分隔。它不是前端配置，不使用姓名或`isAdmin`参数提权。

环境变量生效并重新部署后，从同一个小程序调试器调用：

```javascript
wx.cloud.callFunction({name:'campusApi',data:{action:'initialize'}})
  .then(r => console.log(r.result));
```

初始化建立14个集合并写入5餐厅、10个示例窗口、30道示例菜品。云端不导入示例用户、评价、拥挤度和投票，避免将演示记录误认为真实用户数据。已有 revision 元数据时初始化返回现有数据，不提供清空生产数据入口。1.1版增加mealPlans集合，已部署环境也应重新上传两个云函数，再由一位管理员调用initialize补齐新集合并设置其权限。只由一位管理员执行初始化。

创建后再次检查所有集合的客户端权限，详见上一节。重新编译小程序，到“我的”登录。管理员应能打开管理台，普通用户调用管理接口应返回拒绝。

## 四 配置内容安全

`campusApi/config.json` 声明 `security.msgSecCheck` 和 `security.imgSecCheck` 云调用权限；微信控制台需为当前AppID开通相应能力。文本使用版本2、场景2；图片使用同步接口，限制为1MB内JPG/PNG。

实际流程：文本检查 → 每张图片检查 → 将已检查字节复制到客户端不可写的verified目录 → 保存为待人工审核 → 管理员通过 → 公开。机器检查失败或接口不可用都不保存新评价。未完成机器检查的记录，即使管理员也不能直接公开。

若当前AppID或微信规则要求改用 `mediaCheckAsync`，需要按官方接口补上结果回调、可信回调验签和状态更新后再公开；不能把“已提交异步检测”当作“已通过”。本包未接入异步回调，不声称兼容所有账号能力。

图片上传：客户端先向 `uploadTicket` 申请30分钟凭证，取得专属随机路径，调用 `wx.cloud.uploadFile`，再把fileID交给评价接口。服务端核对用户路径、凭证、文件实际格式和大小，再检查并冻结图片。原上传文件即使之后被覆盖，也不会改变评价绑定的冻结副本。旧版reviews路径图片暂不签名，作者编辑评价后会重新检测冻结并送人工审核。内容安全出错时上传文件可能仍在云存储；也可能留下因评价保存失败而未被引用的冻结副本；应按票据过期时间和评价引用定期检查未引用文件，正式使用前补充资源清理策略。

上线前在微信公众平台补齐隐私指引，说明昵称、用户主动选择的图片、评价、收藏和上报用途；按当前平台要求配置图片选择能力声明。项目不读取手机号、精确位置或通讯录。

## 五 配置饭点订阅

1. 在微信公众平台选择适用的**一次性订阅模板**，记录真实模板ID和模板字段名。
2. 客户端 `config.js` 的 `subscribeTemplateId` 填真实ID。
3. 两个云函数均配置 `SUBSCRIBE_TEMPLATE_ID`，保持同一模板。
4. 在 `notifyMeals` 配置 `SUBSCRIBE_DATA_JSON`，字段名必须与所选模板完全一致。例如，只有在真实模板确实有 `thing1`、`time2` 时才可使用以下值：

```json
{"thing1":{"value":"到饭点啦，来看看食堂有什么"},"time2":{"value":"{time}"}}
```

5. 在 `notifyMeals` 配置 `MINIPROGRAM_STATE=developer` 用于开发验收，体验版改为 `trial`，正式版改为 `formal`。
6. 按 `notifyMeals/config.json` 创建每分钟一次的云端定时触发器。核对平台控制台是否已创建成功；仅上传文件不能作为触发器生效的证明。函数按UTC+8判断11:30和17:30。
7. 用户必须在“我的→口味提醒”点击午餐或晚餐并允许微信弹窗，服务端才记录一个待发送名额。平台最终仍会核验真实授权。
8. 到选定时间检查函数日志与真实微信收信。成功后状态为sent、remaining为0；下次需重新主动授权，不提供默认长期订阅。

发送占用和结果更新均使用事务递增appMeta的revision，防止与客户端改写额度竞争；发送前先占用名额，避免两个触发器并发重复发送；失败保留failed状态供管理员核对，不自动重试不明结果。每分钟最多处理100条待发送提醒，适合课程演示；大规模使用前应补充分页与发送队列。

## 六 最终真实验收

| 项目 | 必须看到的证据 |
| --- | --- |
| 微信身份 | 两个不同微信用户的本人记录互不串号；退出后个人中心恢复未登录 |
| 云共享 | A用户上报，B用户30秒内刷新看到；A用户收藏不出现在B的个人中心 |
| 管理权限 | 普通用户手工调用moderate/saveCatalog返回拒绝 |
| 内容检查 | 不合规文本、错误图片被拦截；接口断开时内容不公开 |
| 人工审核 | 待审仅作者与管理员可见；通过后其他用户能看且评分变化；作者改文后旧审批凭据被拒绝 |
| 冻结图片 | 客户端上传reviews成功；写入、覆盖、删除verified均被拒；修改原图不改变已绑定副本；无权用户不能直接读存储 |
| 提醒 | 真实授权、到点收信、额度归零；拒绝授权不保存提醒 |
| 兼容 | 开发者工具无编译错误，至少一台iOS和一台Android检查布局、图片、键盘、返回导航 |

## 1.2升级顺序

保留数据库与Storage。更新小程序、两个云函数和客户端存储规则；执行initialize确认14集合存在；应用storage.rules.json并验证verified路径拒写；配置ACK变量后才启用图片上传。新的moderate接口要求expectedToken，应同步更新管理页面，旧客户端不能继续审批。旧图作者重新送审，不批量删除原记录。

## 1.3五餐厅目录升级

新环境初始化即包含基础园餐厅、湖畔餐厅、翔远餐厅、鸿鹄餐厅、莘子园餐厅。窗口、菜品、价格为示例，位置、楼层、营业时间待核实。云环境初始化仍不导入示例用户、评价和客流。

已有云环境：先备份数据，再同步部署客户端与campusApi云函数；管理员登录小程序管理台，点击“升级旧版五餐厅目录”并核对说明。服务端校验管理员身份、默认目录关联和扩展ID，事务补充新目录并记录操作。原收藏、评价、计划和已修改价格保留；原餐厅名只替换旧默认名称，不覆盖管理员自定义名称。遇到自定义ID冲突会拒绝整次升级，应在食堂、窗口、菜品管理中手动整理，不能清空数据库解决。initialize不会覆盖现有目录。

本地演示仅在识别到旧版默认目录且无冲突时自动升级，空云快照不会注入示例数据。1.2版云存储规则与SECURE_STORAGE_RULES_ACK=v1.2继续沿用，1.3不改变该配置标记。
